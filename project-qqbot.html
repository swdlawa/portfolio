一个会自己爬起来的机器人

最初只是想让群里有个能接话的角色。做着做着发现，让模型说话不难，让它连续几周不掉线才难。

角色
独立开发
时间
2026.05
技术栈
NoneBot2 · NapCat · DeepSeek API
结果
稳定运行数月

想做成什么样

需求列出来只有四条：有固定人设、能记住上下文、能看懂图片、能定时提醒。技术上就是一条链路：QQ 消息进来，交给模型，再把回复发回去。

难点在于这条链路不能只跑一次。群里的消息是随时来的，机器会重启、网络会断、接口会超时。一个只在演示时能用的机器人，没有意义。

技术选型

  • NoneBot2 做消息分发和插件管理，Python 生态，改起来快；
  • NapCat 负责和 QQ 通信，走 OneBot 11 协议；
  • DeepSeek API 负责生成回复，人设写进 system prompt；
  • WebSocket 长连接 替代 HTTP，用来接收事件。

那个让我卡了一晚上的问题

按文档配好 HTTP 适配器，启动日志显示一切正常，但机器人对消息完全没有反应。日志里全是“成功”，端口却没有任何连接。

查了很久才确认：适配器报告的是配置加载成功，并不代表它真的在监听。换成 WebSocket 长连接之后，事件立刻就能收到。

“只报成功、不监听端口”——这类问题最耗时间，因为所有日志都在骗你。

这件事之后，我加了两层保险：写了一个守护进程，进程挂了自动拉起；再配开机自启，机器重启也不用管。判断服务是否健康，用一个真实的探活请求，而不是看日志最后一行。

记忆是怎么做的

没有上向量数据库，就是按会话保存最近若干轮对话，超出长度就截断。够用，也便宜。人设通过 system prompt 固定，避免它聊着聊着变成另一个人。

图片识别是把图片转成模型能接受的输入再提问。这部分准确率一般，所以我不会让它对图片内容做重要判断。

边界

  • 上下文一长就贵，所以只保留最近几轮，不做长期记忆；
  • 模型偶尔会胡说，涉及事实的内容我会让它明确说“不确定”；
  • 没有做多群隔离的复杂权限，只在熟人小群里用。

我学到什么

以前我以为“部署”是最后一步，现在知道它只是开始。真正让一个服务可用的，是超时、重试、守护和日志这些不性感的部分。也是从这个项目开始，我习惯在任何“成功”日志后面加一句：真的成功了吗？
