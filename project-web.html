Let AI write the code, then own it

This was a university course project and the first time I built front end, API, database and deployment as one piece. AI helped a lot — but every line I committed, I had to be able to explain.

Role
Course project, solo
Time
2026.09 — 11
Stack
Vue 3 · FastAPI · MySQL · Docker
Outcome
A complete, deployable site

What the project is

A web application with login, data management and an admin area. Vue 3 on the front end, FastAPI on the back, MySQL underneath. The features aren't exotic, but "complete" means every layer has to connect: forms validate, endpoints authenticate, the schema exists, and the deployment survives a restart.

Where AI actually helped

  • Scaffolding: project structure, routing, base components — days of documentation reading saved.
  • Boilerplate: CRUD endpoints, form validation, issuing and verifying JWTs.
  • Explaining errors: pasting a stack trace usually pointed me in the right direction.

It also confidently produced code that didn't run: mismatched field names, dependency version conflicts, middleware in the wrong order. You only find those by running it.

How I reviewed it

My method is dumb but effective:

  1. Run it first; if it doesn't run, I don't read it.
  2. Then read it block by block, asking "what happens if I delete this line?"
  3. Write tests for the critical paths so a bad edit is obvious.
  4. Read the diff before committing, and make sure nothing unrelated slipped in.

The clearest example: an AI-generated login endpoint looked fine, but the token expiry was hard-coded so test tokens never expired. Nothing errors. It just becomes a security problem after launch.

AI can write the code, but it can't take responsibility for why that code is there.

Deployment lessons

Everything worked locally; under Docker Compose the API returned 500. My first instinct was the code. It was the database container not being ready before the backend tried to connect. A health check and a retry made it stable.

Reading container logs is the skill of this phase: docker compose logs -f beats guessing by a factor of a hundred.

If I did it again

  • Agree the API contract before generating front and back ends, to avoid field mismatches.
  • Write tests alongside features instead of at the end.
  • Move all configuration into environment variables; never hard-code secrets or timings.
